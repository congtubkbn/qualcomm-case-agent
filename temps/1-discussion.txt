## Session 3 — Phân tích rca-framework & tích hợp qualcomm-agent

### rca-framework tóm tắt (temps/rca-framework.md)
- Cline skill pipeline, RCA cho UE issue, state machine qua 1 JSON state file
- 3 tool ngoài: `spec_query.py` (3GPP spec GraphRAG), `code_search.py` (UE code search),
  `log_query.py` (DuckDB log query, table isolation theo phase)
- Flow: scoping → event timeline → Checkpoint A (confirm top event) → FTA loop
  (build tree → evaluate branch → cross-ref → root cause) → Checkpoint B
  (dig/accept/abort) → finalize report
- Invariant cứng: keyword phải có provenance (trace về tool call, ko lấy từ
  pretrained knowledge), no fix generation (chỉ root cause), user gate bắt
  buộc, iteration budget=5

### Tích hợp qualcomm-case-agent vào rca/
rca-framework đã có pattern 3 tool retrieval (spec/code/log), mỗi tool = 1
skill wrapper, output ghi thẳng vào state file, raw data ko qua stdout.
Qualcomm case cache (`data/cases/<CODE>/case.json`) fit làm **tool thứ 4**
theo đúng pattern này:

- Thêm skill `3gpp-qualcomm-case-retrieval` (song song
  `3gpp-spec-retrieval`/`3gpp-code-retrieval`) wrap đọc case.json local — trả
  summary nén (case metadata + comment excerpt liên quan), ko dump full case
  ra stdout — đúng invariant "raw data never round-trips through stdout".
- Vị trí gắn vào pipeline:
  - **Phase 0/1 (scoping)**: nếu issue đã có Qualcomm case code, seed
    IS/IS-NOT từ case description + enrichment sẵn có → tiết kiệm 1 vòng
    Phase 1.
  - **Phase 3.4 (cross-reference)**: case comment thường chứa chẩn đoán/debug
    request từ Qualcomm engineer — nguồn đối chiếu song song với spec/code,
    KHÔNG thay thế.
  - **Checkpoint A/B**: pull case liên quan ngay trong Cline, khỏi rời
    workflow.
  - **Phase 4 (finalize)**: optional — audit trail nối RCA report ↔ case
    code (không tự động post lên portal, đó là external action cần confirm
    riêng).

**Ràng buộc phải giữ khi tích hợp**:
- Keyword provenance rule phải mở rộng: keyword từ case comment cần tier
  riêng (giống `ENGINEER_PROVIDED` trong v6-coworker design doc, hiện chưa
  implement) — không coi ngang hàng info từ spec_query/code_search vì case
  enrichment là model-generated, chưa qua verify cơ chế.
- Case-agent enrichment (root cause, analysis flow) là **hint, không phải
  authority** — RCA vẫn phải tự re-derive root cause qua spec/code/log theo
  invariant "no fix generation" + "keyword provenance". Tránh double-authority
  conflict.
- NDA constraint đã khớp sẵn: cả 2 hệ thống chạy local-only, không gọi
  external service.

### Giá trị khác ngoài RCA
1. **Case archival/audit độc lập** — full case cache local (JSON/MD/HTML/PDF),
   tra cứu nhanh hơn portal, share PDF cho đồng nghiệp không cần login.
2. **Watch/sync/dashboard tự động** (scheduler.mjs) — theo dõi case trong
   watchlist, biết case nào Qualcomm đã reply / còn open question chờ
   feedback → SLA tracking, khỏi polling tay.
3. **Resume context nhanh** — case dài (vài tuần), enrichment (per-comment
   role/key point/3GPP citation/answered-unanswered) giúp quay lại case cũ
   không cần đọc lại toàn bộ thread.
4. **Nguồn ý tưởng patent** (khớp Session 3 patent idea ở mục 3 trên) —
   corpus case + citation 3GPP sẵn có là input tốt để mine gap trong spec →
   patent idea, độc lập RCA.
5. **Precedent search** — cache case tích lũy theo thời gian thành corpus tìm
   case tương tự đã từng gặp → giảm effort trước khi chạy RCA đầy đủ.
6. **Design pattern tái dùng** — nguyên tắc "capture = code (0 token),
   analysis = model" của case-agent là mẫu cho constraint "tiết kiệm token" ở
   mục 4 — RCA's 3 tool wrapper cũng theo nguyên tắc này.
